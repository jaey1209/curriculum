## 사용자(현직 교사, 연수 담당)가 정한 것

- **연수 버전 2가지.** 기본(기본값): 출결 마감·성적 마감(1·2단계)은 담당 부서가 끝낸 상태로 시작, 업무담당자가 3~8단계를 직접 누름.
  심화: 1·2단계에 일부러 빠진 마감이 있어 어디서 막히는지 찾는 연습. 링크 뒤 `#심화`(또는 `#기본`), 관리자 화면에서도 전환.
- 5단계(이수여부 처리)는 실제 담당 교과담임, 7단계(학생부 자료반영)는 실제 담당 학급담임으로 화면·말풍선·흐름도에 표시. 3·4·6·8단계는 업무담당자.
- 학업중단 학생 학적반영은 학적 담당자 일이라 흐름에서 뺌(가상 자료에 자퇴 학생 없음).
- 헤더에 저작권 표시 `© 2026 Jae-Young Lee`.
- **업무진행(2026-11)**: 연수도우미 메뉴·상단 버튼은 없앰. 나이스 메뉴는 모두 그대로 둠. 왼쪽 아이콘 줄의 🔔을 누르면 옆에 작은 창으로
  "최성보 업무진행" 진행 현황(완료 수·막대, 1~8단계 세로 목록, 끝난 단계 ✔·지금 단계 '진행 중', 누르면 그 화면으로 이동)이 뜨고, 맨 아래 작게 [처음부터]·[관리].
  🔔 배지는 지금 단계 번호. ⚙(환경설정) 아이콘도 관리 화면으로 감. 첫 화면(초기화면)은 제목과 [▶ 3단계 … 시작하기] 버튼만.
- **업무 탭별 작업(2026-11)**: 상단 업무 탭이 실제로 동작함(`cond.role`, 기본 최성보업무). 작업마다 맞는 탭에서만 가능(`ACTION_ROLE`):
  교과담임 = 3~6단계(대상자 가져오기·예외처리·이수관리·학점반영·마감), 교시 출결마감·학기별과목마감, 정기시험/수행평가 마감 / 학급담임 = 7단계 학생부 자료반영, 일일 출결마감 /
  최성보업무(업무담당자) = 8단계 마감정보저장·상신, 과목전체마감·성적산출전체마감·승인요청·결재(연수용). 다른 탭에서 누르면 "상단 [○○] 탭에서 할 수 있어요" 알림, 입력칸은 잠김.
  최성봇은 탭이 다르면 첫 순서로 "상단 [○○] 탭을 누르세요"(해당 탭 주황 강조), [데려다줘]는 탭까지 바꿔 줌. 헤더 [최성봇]은 ON/OFF 스위치.
- **헤더(2026-11)**: 사용자가 보여 준 실제 나이스 헤더 모양을 따름(파란 띠: 학교명 칩·업무담당자·로그인 유지 시간·[최성봇]·[로그아웃]·[사용자지원]·확대 버튼, 아래 흰 줄: 업무 탭).
  실제 교육청 로고·이름, 실제 학교명·사용자 이름·아이디는 넣지 않음. 업무 탭은 업무분장설정업무·최성보업무·학급담임·교과담임(부서장(정보공시부) 삭제).
- **2026-11 플레이 테스트 반영**: 실습 과목은 공통수학2 하나(공통국어2·공통영어2는 3~6단계 완료 상태로 시작).
  공통수학2 시나리오(대상자 7명): 2반 5번 = 특수교육대상자(예외), 3반 20번 = 5시수(미이수), 나머지 8~12시수(이수).
  시나리오는 화면 상자 대신 최성봇이 알려 줌: 말풍선 안 노란 '연수 시나리오' 칸(3~6단계), 4·5단계 화면에 처음 들어오면 한 번 펼쳐짐, 표를 누르면 한 줄로 접힘.
  참여시수·예외사유 입력은 화면 전체를 다시 그리지 않고 그 행만 갱신(첫 클릭 손실 방지), Tab·Enter로 다음 학생 칸 이동.
  [처음부터 다시]·흐름도 초기화 버튼은 확인 후 바로 초기화(최성봇 위치·대화·열린 탭 포함). 탭 기능 자체는 확정이라 손대지 않음.

- 대상: 최소 성취수준 보장지도(추가학습) **업무 담당자 연수**. 교육청 안내 PDF의 8단계 흐름만 다룸.
- 첫 화면은 [로그인] 버튼 하나. 접속자는 업무담당자 1명이 모든 단계(교과담임·학급담임·결재 포함)를 처리.
- 학교명 `재영고등학교`. 실존 인물 이름은 넣지 않음. 교사·학생 이름은 모두 성만 남기고 `이**`처럼 가림. 상단 머리글은 "업무담당자"만 표시.
- 업무승인은 **탭이 아니라 {승인요청} 버튼을 누르면 뜨는 팝업**. 결재는 연수용 [결재완료 처리(연수용)] 버튼으로 대신함.
- 연수 도우미 챗봇 이름 **최성봇**: 오른쪽 아래 기본 위치(말풍선은 한 줄 요약으로 접혀 있고 누르면 펼침, 말풍선·채팅창은 항상 화면 안에 배치, 알림창보다 아래), 마우스로 끌어 이동, 말풍선에 지금 누를 버튼을 직접 안내,
  [데려다줘]·[가−][가+] 버튼, 대화(채팅) 기능은 뺌(2026-11, 답의 근거를 지침으로 보장할 수 없어서) — 로봇을 누르면 말풍선 펼치기·접기, 눈은 흰 타원만(눈동자 없는 버전), 말투는 친근한 "~해요"체.
- 노안 고려: 말풍선은 큰 글씨(핵심 19px), 채팅 15px.
- 채팅창 아래 빠른 답변 버튼 줄은 없앰. 예외처리 화면의 '예외' 열은 3번 단계, [저장]은 4번.
- 관리자(기록 관리): 로그를 연수일별로 보고 날짜별 삭제·전체 삭제·전체 초기화.

   기안문서상신 팝업을 실제와 맞춤. 영상(video1.mp4)은 클라우드에서 못 받았지만 캡처로 충분했음.
2. 캡처에 없는 화면(출결관리(일일)·과목별 출결관리 교시 마감·정기시험/수행평가마감관리·로그인)은 추정으로 만든 것이라 실제와 다를 수 있음.
3. 브랜치 이력의 옛 커밋에는 지운 인물명이 남아 있음(강제 푸시가 막혀 정리 못 함). 사용자가 원하면 이력 정리 필요.
4. 원래 있던 교과서 선정 앱(`web/index.html`, README 서식3 설명)에도 같은 인물명이 있음. 사용자 확인 전까지 그대로 둠.

## 고칠 때 지킬 것

- 화면을 바꾼 뒤에는 꼭 `neis/tests/teacher-walk.js`를 돌려 8단계가 끝까지 가는지 확인.
  화면의 버튼만 클릭(주황색 다음 버튼, [데려다줘], 확인창 [확인], 점선 칸 입력)해서 로그인부터 완료까지 진행하는 테스트.
  ```bash
  node neis/tests/teacher-walk.js   # 마지막 줄 steps가 모두 true, ERRORS []면 통과 (HASH=심화 로 심화 버전)
  VW=1471 VH=812 node neis/tests/playtest.js   # 플레이 테스트 확인 항목 52개 (클릭 손실·Tab·가림·네 모서리·초기화)
  ```
  (Playwright 필요. 스크린샷은 OS 임시 폴더나 `OUT` 환경변수 폴더에 저장)
- 다음 단계 안내는 `nextAction()` 한 곳에서 계산함. 화면 버튼에 `id`(예: `b-query`, `b-fetch`, `b-save`, `b-modal-ok`)를
  붙이고 `seq` 항목의 `b`로 연결하면 번호·주황 강조·말풍선 안내가 자동으로 따라옴.
- 수정 후 아티팩트도 갱신하면 사용자가 같은 링크에서 바로 확인 가능.
