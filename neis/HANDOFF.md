## 사용자(현직 교사, 연수 담당)가 정한 것

- 대상: 최소 성취수준 보장지도(추가학습) **업무 담당자 연수**. 교육청 안내 PDF의 8단계 흐름만 다룸.
- 첫 화면은 [로그인] 버튼 하나. 접속자는 업무담당자 1명이 모든 단계(교과담임·학급담임·결재 포함)를 처리.
- 학교명 `재영고등학교`. 실존 인물 이름은 넣지 않음. 교사·학생 이름은 모두 성만 남기고 `이**`처럼 가림. 상단 머리글은 "업무담당자"만 표시.
- 업무승인은 **탭이 아니라 {승인요청} 버튼을 누르면 뜨는 팝업**. 결재는 연수용 [결재완료 처리(연수용)] 버튼으로 대신함.
- 연수 도우미 챗봇 이름 **최성봇**: 왼쪽 아래 기본 위치, 마우스로 끌어 이동, 말풍선에 지금 누를 버튼을 직접 안내,
  [데려다줘]·[대화하기]·[가−][가+] 버튼, 눈은 흰 타원만(눈동자 없는 버전), 말투는 친근한 "~해요"체.
- 노안 고려: 말풍선은 큰 글씨(핵심 19px), 채팅 15px.
- 채팅창 아래 빠른 답변 버튼 줄은 없앰. 예외처리 화면의 '예외' 열은 3번 단계, [저장]은 4번.
- 관리자(기록 관리): 로그를 연수일별로 보고 날짜별 삭제·전체 삭제·전체 초기화.

## 남은 일 (로컬 세션으로 옮긴 이유)

1. **실제 나이스 화면 반영 — 완료.** 사용자가 준 연수 영상 캡처 PDF 2개(119장, 강사 설명 포함)를 보고 틀·메뉴·주요 화면·
   기안문서상신 팝업을 실제와 맞춤. 영상(video1.mp4)은 클라우드에서 못 받았지만 캡처로 충분했음.
2. 캡처에 없는 화면(출결관리(일일)·과목별 출결관리 교시 마감·정기시험/수행평가마감관리·로그인)은 추정으로 만든 것이라 실제와 다를 수 있음.
3. 브랜치 이력의 옛 커밋에는 지운 인물명이 남아 있음(강제 푸시가 막혀 정리 못 함). 사용자가 원하면 이력 정리 필요.
4. 원래 있던 교과서 선정 앱(`web/index.html`, README 서식3 설명)에도 같은 인물명이 있음. 사용자 확인 전까지 그대로 둠.

## 고칠 때 지킬 것

- 화면을 바꾼 뒤에는 꼭 `neis/tests/teacher-walk.js`를 돌려 8단계가 끝까지 가는지 확인.
  화면의 버튼만 클릭(주황색 다음 버튼, [데려다줘], 확인창 [확인], 점선 칸 입력)해서 로그인부터 완료까지 진행하는 테스트.
  ```bash
  node neis/tests/teacher-walk.js   # 마지막 줄 steps가 모두 true, ERRORS []면 통과
  ```
  (Playwright 필요. 스크린샷은 OS 임시 폴더나 `OUT` 환경변수 폴더에 저장)
- 다음 단계 안내는 `nextAction()` 한 곳에서 계산함. 화면 버튼에 `id`(예: `b-query`, `b-fetch`, `b-save`, `b-modal-ok`)를
  붙이고 `seq` 항목의 `b`로 연결하면 번호·주황 강조·말풍선 안내가 자동으로 따라옴.
- 수정 후 아티팩트도 갱신하면 사용자가 같은 링크에서 바로 확인 가능.
